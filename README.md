# 仁家科技 · 内部积分系统

单文件网页版积分管理系统。**HTML / CSS / JS 全部内联、无外部依赖、无需构建**。

同一份文件能自动适配三种运行环境，**不需要改任何代码**：

| 环境 | 怎么判断的 | 数据在哪 |
|---|---|---|
| **内网服务器**（推荐，多人共享） | 从内网地址打开，如 `http://192.168.1.50:8899/` | 服务器硬盘上，**全公司同一份**，管理员能改、同事只能看 |
| **本机离线**（兜底） | 双击本地 `index.html`，`file://` 打开 | 浏览器 `localStorage`，各自独立 |
| **线上网页**（本仓库 Pages） | 从 `*.github.io` 打开 | 浏览器 `localStorage`，各自独立 |

判断依据就是地址本身：**内网地址自动连服务、公网域名安静地退回单机模式**，
所以不会出现在别人的网站上打开时对一个不存在的接口反复报错的情况。

## 让同事看到数据：部署内网服务器

页面的同步能力由一个**跑在公司内网的服务端**提供（就是 `server` 那个文件夹）。
部署好之后：

- **同事打开网址就看到你录入的最新数据**，不用装软件、不用注册、不用登录
- 你保存后约 0.4 秒推到服务器；同事那边最多 15 秒自动刷新，切回页面时立刻刷新
- **数据只有一份**（服务器硬盘上），不存在"多份副本互相比对"，也就没有谁覆盖谁的问题
- **只有管理员能改**：写入接口要校验口令哈希，端口令直接 401；错 8 次锁 5 分钟
- **断网不丢数据**：改动留在本机并标记待上传，网络恢复后自动补传
- 右上角状态栏实时显示：`已同步` / `正在同步` / `离线` / `本地模式`

完整部署步骤见 `server/部署说明.md`（三步：装 Node.js → 拷文件夹 → 双击 `install-service.bat`）。

> 早先尝试过用云数据库（Supabase）做同步，需要注册账号、执行 SQL、填两个密钥，
> 流程偏重。现已改用公司内网自建服务，一条命令装完，内存占用约 50 MB。

### 管理员密码

管理员密码为**公司统一固定密码**，任何电脑 / 浏览器都用同一个口令：

1. 点右上角「切换身份」
2. 输入管理员密码 → 点「进入管理员模式」（或直接按回车）

- 口令**不保存在浏览器里**，所以换浏览器、清缓存、换电脑都不受影响，也不会随数据导出 / 导入变化。
- 源码里**不写明文口令**，只存它的哈希常量（`ADMIN_HASH`），仓库即使公开托管也不会直接暴露口令。
  - 更换口令：运行 `pwdHash("新口令")`，把结果同时替换 `ADMIN_HASH` 和 `server/config.json` 里的 `adminHash`。
- 忘记口令请联系系统维护人。

## 部署到 GitHub Pages（本仓库）

本仓库已上传至 `https://github.com/ehabmarket16-create/Renjia-jifen`：

1. 打开仓库 **Settings → Pages**
   - Source 选 `Deploy from a branch`
   - Branch 选 `main`，目录选 `/ (root)` → **Save**
2. 等 1 分钟左右，访问 `https://ehabmarket16-create.github.io/Renjia-jifen/`

> 仓库设为 Public 时 Pages 免费可用；Private 仓库开 Pages 需要 GitHub Pro。
> 仓库根目录的 `index.html` 就是系统本体，改名或挪到子目录会导致 Pages 打不开。

**注意：Pages 上的那份是单机版** —— 公网域名下页面不会去连内网服务（也连不上，
浏览器会拦截 HTTPS 页面访问 HTTP 内网接口）。它的用途是：内网服务临时不可用时，
至少还能打开看、能导出。真要多人共享，用上面那节的内网服务器。

| 兑换记录 | 历史兑换明细 |

## 重要说明

- **在内网服务器上运行时，数据以服务器为准**，所有人共享同一份；本机缓存一份，断网时照常可用。
- **不在服务器上运行时，数据存在浏览器本地**（`localStorage`，键名 `jf_system_v1`），换设备不会自动跟过去；
  迁移办法：「规则说明 → 数据管理 → 导出全部数据 (JSON)」备份，再到目标设备「导入 JSON」。
- **服务端权限设计**：
  - `GET /api/state` 读取对所有人放开（同事点开就要能看到）
  - `POST /api/write` 必须带管理员口令哈希，否则 401；连续错 8 次锁定 5 分钟
  - `POST /api/wish` 访客用，只能追加、自动去重、单次限 20 条，改不了已有内容
  - 请求体上限 8 MB；静态文件做了路径穿越防护
- **同步是「最后一次写入生效」（last-write-wins），没有冲突合并。** 如果**两台设备同时**都是管理员在改，
  后保存的那台会覆盖前一台。实际使用中管理员只有一个人，且页面每 15 秒自动拉最新，风险很低；
  但请避免"电脑和手机同时开着管理员页面各改各的"，同一时刻只在一台设备上录入最稳。
- **管理员口令是「防误操作 + 防乱改」级门禁，不是强安全机制。** 局域网内通信是明文 HTTP，
  同网段里懂技术的人可以抓包看到口令哈希。对「公司内部积分表」这个场景够用；
  如果哪天要暴露到公网，务必先加 HTTPS。
