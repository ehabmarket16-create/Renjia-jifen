# 仁家科技 · 内部积分系统

单文件网页版积分管理系统。**HTML / CSS / JS 全部内联、无外部依赖、无需构建**。

支持两种运行模式，**同一份文件自动切换**：

| 模式 | 触发条件 | 数据在哪 |
|---|---|---|
| **云同步模式**（多人共享） | 填了数据库配置（`SB_URL` / `SB_KEY`） | 云端数据库，**所有人看到同一份**，你能改、同事只能看 |
| **纯本地模式**（离线可用） | 没填配置，或网络不通 | 浏览器 `localStorage`，各自独立 |

## 直接使用

双击 `index.html` 用浏览器打开即可（未配置数据库时为纯本地模式）。

## 云同步（让同事看到你录入的数据）

页面的数据层支持接一个 Supabase 数据库，接上之后：

- **同事打开网址即看到你录入的最新数据**，不再是各自浏览器里的空数据
- 你保存后约 0.4 秒推送到云端；同事那边最多 15 秒自动刷新，切回页面时立刻刷新
- **只有管理员能改**：数据库层面没有开放写入权限，写入必须走带口令校验的函数
- **断网不丢数据**：改动留在本机并标记待上传，网络恢复后自动补传
- 页面右上角状态栏实时显示：`已同步` / `正在同步` / `离线` / `本地模式`

开通步骤见工作区里的 `云同步配置指南.md`（注册 Supabase → 执行 `supabase_setup.sql` → 把 Project URL 与 anon key 填进 `var SB_URL` / `var SB_KEY`）。

### 管理员密码

管理员密码为**公司统一固定密码**，任何电脑 / 浏览器都用同一个口令：

1. 点右上角「切换身份」
2. 输入管理员密码 → 点「进入管理员模式」（或直接按回车）

- 口令**不保存在浏览器里**，所以换浏览器、清缓存、换电脑都不受影响，也不会随数据导出 / 导入变化。
- 源码里**不写明文口令**，只存它的哈希常量（`ADMIN_HASH`），仓库即使公开托管也不会直接暴露口令。
  - 更换口令：运行 `pwdHash("新口令")`，把结果替换 `ADMIN_HASH` 即可。
- 忘记口令请联系系统维护人。

## 重要说明

- **未配置数据库时，数据存在浏览器本地**（`localStorage`，键名 `jf_system_v1`），换设备不会自动跟过去；
  迁移办法：「规则说明 → 数据管理 → 导出全部数据 (JSON)」备份，再到目标设备「导入 JSON」。
- **配置数据库后，数据以云端为准**，所有人共享同一份。本机仍会缓存一份，断网时照常可用。
- **数据库权限设计**（对应 `supabase_setup.sql`）：
  - 读取对所有人放开（同事点开就要能看到）
  - 表上**没有** INSERT / UPDATE / DELETE 策略，并回收了这些权限 → **拿到 anon 密钥也无法直写**
  - 管理员写入走 `jf_admin_write`（校验口令哈希）
  - 访客心愿走 `jf_wish_append`（只能追加、自动去重、单次限 20 条）
- **云同步是「最后一次写入生效」（last-write-wins），没有冲突合并。** 如果**两台设备同时**都是管理员在改，
  后保存的那台会覆盖前一台的改动。实际使用中管理员只有一个人，且页面每 15 秒自动拉最新，风险很低；
  但请避免"电脑和手机同时开着管理员页面各改各的"。同一时刻只在一台设备上录入最稳。
  - 顺带一个同源的小窗口：访客新提交的心愿，若管理员在 **15 秒内**保存，可能被管理员的整份覆盖。
    介意的话，让访客提交后稍等片刻再让管理员点保存。
- **管理员口令仍是「防误操作」级门禁，不是强安全机制。** 口令哈希在前端代码里（公开仓库可见），
  所以这层的真实意义是：**即使有人绕过前端按钮，也删不掉 / 改不了整张表的数据**。
  要防住有备而来的攻击者，需要换成真正的服务端登录（Supabase Auth）。
  好处是：仓库里不含任何明文口令（只存哈希常量），公开托管不会直接泄露凭据。
